# Техническая настройка

## Основа

- Editor: **Unity 6000.6.6f1**, версия зафиксирована в `ProjectSettings/ProjectVersion.txt`.
- Основа — официальный установленный шаблон `com.unity.template.2d-cross-platform-2d` 7.0.0: сохранены штатные URP-настройки, сцены шаблона и GUID.
- URP 2D Renderer, ортографическая камера.
- Input System, активный новый ввод взят из шаблона.
- Unity Localization 1.5.13 (вместе с Addressables): локали `ru` (исходный язык проекта) и `en`; язык системы без перевода откатывается на английский.
- Версии зависимостей перечислены в `Packages/manifest.json`; разрешённые зависимости фиксирует Unity в `packages-lock.json`.
- Unity Version Control, Visual Scripting и обучающий framework убраны из прямых зависимостей: для этого Git-проекта они сейчас не нужны.

Шаблон извлечён напрямую из установленного архива, поскольку первоначальная команда CLI создания проекта завершилась ошибкой чтения реестра Unity Hub. Дальнейшее создание сцен выполняется через настоящий Unity Editor API. Установка новых версий Editor и переключение проекта не происходили.

## Стартовые сцены

`Bootstrap`: камера URP 2D и пустой корень `Systems`. Будущее место запуска сохранений и загрузки мира. Сейчас она не загружает вторую сцену автоматически.

`Prototype_Traversal`: камера URP 2D, корни `World`, `Gameplay`, `UI` и точка `PlayerSpawn`. Это пустая основа для следующего этапа; контроллера, платформ, UI и врагов ещё нет.

В списке сборки: сначала Bootstrap, затем Prototype_Traversal. Список заменяется генератором только если он пуст или содержит лишь штатную SampleScene. Собственный пользовательский список не затирается.

Не изменять `.unity` и `.asset` вручную без необходимости. Использовать Editor API или инспектор, сохранять существующие GUID.

## Ввод

`AliceInput.inputactions` содержит карты `Gameplay` и `UI` и назначен общим Input Actions asset проекта. Генератор заменяет только пустую настройку или исходную настройку шаблона, сохраняя последующий пользовательский выбор. Пока это схема действий; компоненты для её использования будут добавлены вместе с игровым контроллером и интерфейсом.

| Действие | Клавиатура / мышь | Геймпад |
| --- | --- | --- |
| Move | WASD | Левый стик / крестовина |
| Jump | Space | South / A |
| Attack | Левая кнопка мыши | West / X |
| Evade (подкат) | Left Shift | East / B |
| Parry | F | RT |
| Interact | E | North / Y |
| Heal | Q | LB |
| UseAbility | Правая кнопка мыши | RB |
| Map | M | Select |
| Pause | Escape | Start |

Схема предварительная. Evade — подкат. Parry добавлен генератором в существующий asset без изменения прежних привязок. Веер отдельной кнопки не получает: он срабатывает повторным нажатием Jump в воздухе (GDD 0.13). Кнопки следующей способности нет: особый приём выбирается на отдыхе и применяется UseAbility (GDD 0.20).

## Локализация

Настройки — `Assets/_Alice/Settings/Localization/LocalizationSettings.asset`, назначены активными в проекте. Исходная локаль проекта — `ru`, вторая — `en`. Генератор создаёт настройки, локали и таблицу `UI` только при их отсутствии и не меняет выбранный позже язык проекта.

Видимые игроку строки хранятся только в таблицах `Assets/_Alice/Data/Localization`; текстуры с надписями — локализуемые ассеты. Шрифты с кириллицей и латиницей ещё не выбраны: их подключаем вместе с первым интерфейсом, после проверки лицензии.

## Повторная настройка

В Editor: `Alice → Project → Configure Foundation`. Перед ручным запуском Unity предложит сохранить изменённые сцены. Существующие сцены и Input Actions asset не заменяются. Настройки продукта, 2D и сериализации команда приводит к исходной конфигурации.

CLI из корня проекта:

```powershell
unity run C:/Projects/alice --editor-version 6000.6.6f1 --timeout 600 --log-file C:/Projects/alice/Logs/setup.log --no-tail -- -nographics -executeMethod Alice.Editor.AliceProjectSetup.ConfigureBatch
```

CLI самостоятельно управляет batch-флагами и завершением; дополнительный `-quit` ему передавать не надо. Не запускать batch-Editor одновременно с обычным Editor для того же проекта.

## Управление открытым Editor

С 3 ноября 2026 в проект добавлен пакет Unity Pipeline (`com.unity.pipeline` 0.9.1-exp.1, экспериментальный). Через него CLI работает с уже открытым Editor, закрывать его ради batch-режима не нужно. `unity status --json` показывает Editor с состоянием `ready`. Пока идёт перезагрузка домена, команды отвечают `EDITOR_NOT_RUNNING`; через несколько секунд их можно повторить.

Основные команды (`unity command --project-path C:/Projects/alice …`):

| Задача | Команда |
| --- | --- |
| Перекомпиляция | `script recompile`, затем `script recompile_status` до `completed` |
| Ошибки и исключения | `console status`, `console get`, `console clear` |
| Пункт меню, например `Alice/Prototype/Attach Alice Sprites` | `editor invoke_menu` |
| Тесты | `test run`, `test status` |
| Вход и выход из Play | `editor.playmode start`, `editor.playmode stop` |
| Снимок игры | `capture game_view` |

`capture game_view` без `save_path` возвращает PNG в ответе в base64. С `save_path` файл ложится внутрь `Assets/` даже при пути от корня проекта, поэтому снимки сохраняются вне проекта.

Порядок: сначала Pipeline при открытом Editor, batch — только когда Editor закрыт.

Перед `script recompile` проверить, что Editor не в Play: перезагрузка домена во время игры ломает ввод в этой сессии (исключение в `PlayerInputReader.OnEnable`), пока Play не перезапустят.

### Проверка в Play без фокуса

Свёрнутый в фон Editor почти не обновляет кадры, и переход между комнатами M3 в Play не доходит до конца. Перед такой проверкой нужно вызвать `editor.playmode set_run_in_background --enable true`, а после — `--enable false`.

Пока Editor в фоне, Input System отбрасывает события клавиатуры и мыши, поэтому `runtime simulate_key` и `simulate_pointer` до игры не доходят. Для агентов есть меню `Alice/Automation` (`Alice.Editor.AlicePlayAutomation`), только для Play и ничего не сохраняет:

| Пункт | Что делает |
| --- | --- |
| `Press Attack`, `Press Parry`, `Press Interact`, `Press Jump` | Нажимает настоящую кнопку мыши, F, E или пробел на 0,15 с, записывая состояние прямо в устройство внутри игрового обновления ввода; действия видят обычное нажатие. Сама включает режим ввода из следующей строки, который сбрасывается при перезагрузке скриптов |
| `Put Alice Beside Nearest Enemy` | Ставит Алису в 2,4 тайла перед ближайшим живым врагом, разворачивает к нему и переносит туда камеру |
| `Open Nearest Enemy` | Открывает ближайшего врага, как удачное парирование: узкие окна через меню не поймать |
| `Stun Nearest Enemy` | Ранит ближайшего врага до порога оглушения, после чего его можно казнить (`Press Interact`) |
| `Defeat Alice` | Убивает Алису, чтобы посмотреть поражение и пробуждение |
| `Delete Save` | Удаляет сохранение, чтобы прототип начался с чистого листа |
| `Give 50 Decrees` | Даёт Алисе 50 указов, чтобы быстро проверить потерю |
| `Press Heal` | Нажимает Q — нюхательная соль |
| `Press Slide`, `Press Ability` | Нажимает Left Shift (подкат) или правую кнопку мыши (особый приём) |
| `Fill Confidence` | Заполняет уверенность, чтобы попробовать приём без боёв |
| `Capture Screen` | Рендерит камеру вместе с HUD в размере Game view в `Temp/AliceCaptures/screen-NNN.png`: на время снимка холсты HUD переводятся на камеру, поэтому работает и в фоне |
| `Reset Enemies` | Возвращает всех врагов на посты живыми, как будет делать отдых в M3 |
| `Capture Camera` | Рендерит главную камеру в `Temp/AliceCaptures/capture-NNN.png` (640×360) |
| `Route Input To Game View` | На время сессии направляет весь ввод в игру; для событий от Pipeline этого мало, но полезно при ручной игре в фоне |
| `Log Input State` | Пишет в консоль устройства, их состояние и настройки ввода |

`capture game_view` копирует окно Game с экрана: пока оно скрыто или Editor в фоне, снимок остаётся прежним. Для проверки надёжнее `Capture Camera`.

Чтобы разглядеть быстрое действие, время замедляют: `runtime set_time_scale --scale 0.05`, затем снимки `capture game_view` с паузой около 0,45 с, после — `--scale 1`. При 0,05 укол Алисы (0,37 с) длится около 7 секунд, и 16 снимков покрывают его целиком. Слишком сильное замедление (0,02) растягивает удар дольше, чем идёт серия снимков. Положение Алисы в сцене эти команды не меняют: `gameobject set_transform` в Play запрещён, а правка сцены до Play требует ручного возврата.

## Прототип M1

Сцена `Prototype_Traversal` собирается командой `Alice → Prototype → Build Traversal Room` или в batch-режиме методом `Alice.Editor.AlicePrototypeBuilder.BuildBatch`. Генератор создаёт только недостающее: серый тайл, `Data/Player/AliceMovement.asset`, префаб `Prefabs/Characters/Alice.prefab`, Pixel Perfect Camera (16 пикселей на юнит, 640×360, Upscale Render Texture), слежение камеры и комнату `World/GreyRoom`. Геометрию комнаты пересоздаёт отдельная команда `Rebuild Grey Room Geometry` (в batch-режиме — `RebuildRoomBatch`); остальная сцена при этом сохраняется.

Камера (`CameraFollow2D`) всегда стоит на целое число экранных пикселей от Алисы. Картинка рисуется в 640×360, поэтому камера и Алиса попадают каждая на свой пиксель. Если округлять их по отдельности, при движении камеры Алиса дрожит относительно экрана на 1 px (замечание владельца, 8 ноября 2026). С привязкой Алиса на экране стоит ровно, а мир сдвигается целыми пикселями. У края комнаты камеру останавливают границы, они лежат на целых тайлах.

Один тайл — один юнит; линии сетки на блоках служат линейкой. Полоса препятствий слева направо: уступы высотой 2, 3, 4 и 5 тайлов; провалы шириной 3, 4 и 5 тайлов; веер A01 (жёлтый блок); провал 6 тайлов; три сквозные платформы через 4 тайла; тоннель высотой 2 тайла, где проходит только подкат; стена высотой 6 тайлов для прыжка с веером. Внизу — зона опасности, которая возвращает Алису на последнюю опору, где обе ноги стояли на земле.

Управление в прототипе: Move, Jump (повторное нажатие в воздухе после получения веера — порыв), Evade — подкат, «вниз + Jump» на сквозной платформе — спрыгнуть. Метрика игры зафиксирована в коде (GDD 0.14, раздел 12). `Alice.Core.WorldMetrics` — разрешение, пиксели на юнит, тайл. `Alice.Player.TraversalMetrics` — скорость бега, высота и время прыжка, ускорение падения, порыв веера, скорость и длительность подката, размеры тела и пределы комнат; полоса препятствий строится из этих пределов. В `AliceMovement.asset` остались только параметры ощущения: разгон и торможение, допуск края, буферы, обрезка прыжка, неуязвимость и перезарядка подката. Их можно менять в инспекторе во время игры. Значения:

| Параметр | Значение |
| --- | --- |
| Бег | 7,5 тайла/с, разгон 0,08 с, торможение 0,06 с |
| Прыжок | 4,2 тайла, подъём 0,38 с, падение ×1,8, обрезка при отпускании ×0,45 |
| Допуск края / буфер прыжка | 0,1 с / 0,12 с |
| Порыв веера | +3 тайла, один до приземления |
| Подкат | 12 тайлов/с, 0,35 с, неуязвимость 0,04–0,26 с, перезарядка 0,3 с |
| Тело Алисы | 0,75 × 2,85 тайла стоя, 0,75 × 1,1 в подкате |

Скорость прыжка учитывает шаг физики, поэтому заданная высота достигается точно. Всё движение считается в `FixedUpdate` и не зависит от частоты кадров.

Стоя Алиса дышит: в `AliceSprites` четыре кадра `_idleBreath` по 0,3 с (`_idleFrameTime`). Цикл начинается с кадра стойки при каждой остановке, поэтому переход из бега, приземления или удара не дёргается. После `_idleFidgetDelay` (6 с, округляется вверх до целых вдохов) один раз играет `_idleFidget` — левой рукой она приподнимает подол и разглядывает его, через правое плечо поворачивается вполоборота к камере, отставив правую ногу, смотрит на подол у этой ноги, поворачивается обратно и отпускает подол, 16 кадров по 0,15 с (`_idleFidgetFrameTime`), — и дыхание начинается заново.

Тесты: `unity test C:/Projects/alice --mode EditMode` (расчёт прыжка, буфер ввода, соответствие параметров пределам комнат, целое масштабирование разрешения) и `--mode PlayMode` (высота прыжка, короткий прыжок, разгон, порыв веера только с A01, подкат под низким потолком, нет прыжка после запаса на сход с края и в падении вдоль стены).

## Боевой прототип M2

Для проверки боя есть отдельная сцена `Prototype_Combat` (`Alice → Prototype → Build Combat Arena`, в batch-режиме — `BuildArenaBatch`): ровная арена 40 тайлов, Алиса в центре, по солдату в 12 тайлах с каждой стороны, за пределами их обзора. Сцена один раз создаётся копией `Prototype_Traversal`, поэтому камера, свет и Алиса те же; повторный запуск лишь восстанавливает пол и стены и не трогает перенесённое и настроенное. Сцена добавлена в Build Settings.

Начат 3 ноября 2026. `Alice → Prototype → Build Traversal Room` (и `BuildBatch`) теперь вызывает `Alice.Editor.AliceCombatSetup`. Он добавляет на префаб Алисы `Health`, `PlayerAttack`, `PlayerDamageReaction`, `DamageFlash` и серую иглу `ThrustMarker`; создаёт `Data/Player/AliceCombat.asset`, данные солдата `Data/Enemies/CardSoldier.asset`, кадры `Data/Enemies/CardSoldierSprites.asset` и префаб `Prefabs/Enemies/CardSoldier.prefab`; ставит солдата в комнату на x = 78 (ровный пол после провала для веера), если врага там ещё нет. Существующие значения не перезаписываются. `Alice → Prototype → Attach Combat Components` делает то же для префабов и данных, не открывая сцен.

Устройство:

- `Alice.Core`: `IDamageable` и `HitInfo` — удар знает только цель; `IHitImmunity` — подкат отменяет попадания на кадрах неуязвимости; `PlayerPresence` — положение Алисы для врагов без поиска по имени.
- `Alice.Combat`: `Health` (здоровье и короткая защита после попадания), `MeleeAttackTimeline` (подготовка, удар, восстановление), `MeleeHitbox` (зона удара задаётся числами в данных, а не коллайдером на кадрах), `DamageFlash`, архетип `MeleeEnemy` с данными `MeleeEnemySettings`, кадрами `EnemySpriteSet` и отрисовкой `MeleeEnemyView`.
- `Alice.Player`: `PlayerAttack` (укол иглой; ввод движения заблокирован на всё время удара), `PlayerDamageReaction` (отбрасывание, сброс удара, вздрагивание, при нуле здоровья — поражение и пробуждение в начальной точке, пока нет отдыха M3), `PlayerCombatSettings`.

Тело солдата — кинематический триггер: Алиса и подкат проходят сквозь него, удары его находят. Солдат стоит на посту, подходит в пределах поводка, замахивается, делает шаг вместе с ударом и открыт в восстановлении. Попадание сбивает его в любой момент, кроме самого удара. Копьё идёт на высоте 2,25 тайла, подкат проходит под ним.

Атака — действие Attack: левая кнопка мыши или западная кнопка геймпада. На земле — комбо: укол, а повторное нажатие до конца укола даёт режущий взмах; в воздухе — взмах. Числа каждого удара — блоки `MeleeMove` в `AliceCombat.asset`. Удары нарисованы по 12 кадров PixelLab с подготовкой, вложением веса и проносом (эталон — удар с разворота, 4 ноября 2026); кадры каждой фазы растянуты на её время. Укол: замах 3 кадра / удар 3 / возврат 6, 0,1 + 0,1 + 0,3 с; взмах: 4 / 3 / 5, 0,14 + 0,1 + 0,3 с; удар в воздухе: 5 / 3 / 4, 0,12 + 0,1 + 0,2 с; контратака получила свои кадры (`alice_trial_counter_`, 1 / 3 / 8, игла удерживается вбитой); парирование — 12 кадров по фазам защиты, отбива, удержания и опускания (4 / 3 / 2 / 3, `_parryPhaseCounts` в `AliceSprites`). Игла и следы рисуются скриптом `needle.ps1`: у укола — полосы рывка, у взмахов и отбива — дуга вокруг плеча. Серая полоса иглы `ThrustMarker` нужна только пока кадров нет: настройка удаляет её, как только кадры укола подключены.

| Параметр | Алиса | Карточный солдат |
| --- | --- | --- |
| Здоровье | ясность 100, без защиты после попадания | 3 |
| Удар | укол 0,07 + 0,1 + 0,2 с; взмах 0,08 + 0,12 + 0,28 с; в воздухе 0,06 + 0,12 + 0,2 с; урон 1 | 0,7 + 0,18 + 0,7 с, пауза 0,5 с, урон 20 |
| Дальность | укол 0,2–2,75 тайла, полоса 0,5 тайла на высоте 1,6; взмах 0–2 тайла, полоса 2,6 тайла | 0,3–3,3 тайла и шаг 0,5, атакует с 3,2 тайла, полоса 0,5 тайла на высоте 2,25 |
| Реакция на попадание | отбрасывание 6 × 5 тайлов/с на 0,22 с | оглушение 0,3 с |
| Движение | — | 1,6 тайла/с, обзор 9 тайлов, поводок 7 тайлов |

Выпад солдата переделан 4 ноября 2026 ради читаемости: 11 кадров на холсте 144×64. В замахе (7 кадров на 0,7 с) он опускает копьё, отводит его остриём к груди и отклоняется назад; эта поза держится около 0,4 с. Удар — 2 кадра с вытянутым копьём, урон наносится ровно на них. Возврат — 2 кадра. Дальность 3,3 тайла совпадает с нарисованным остриём.

Тело живого врага — препятствие (GDD 0.21). Тело остаётся триггером, чтобы сквозь него проходили подкат и оружие. Враг реализует `Alice.Core.IBodyBlocker`, и мотор Алисы вне подката останавливает её у такого тела. Если она оказалась внутри, её выталкивает в ближнюю сторону со скоростью `_bodyPushOutSpeed` (6 тайлов/с, `AliceMovement`). Касание ранит на `_contactDamage` (10) в пределах `_contactMargin` (0,1 тайла) от тела, пока враг стоит на посту, преследует или атакует. Подкат через `Alice.Core.IBodyPasser` отключает касание. Сам враг упирается в Алису и в неё не заходит. Отброс задаёт враг: `_knockback` для удара и `_contactKnockback` для касания (`Alice.Core.Knockback`, скорость от врага и вверх плюс время без управления, у солдата 6 × 5 тайлов/с на 0,22 с). Значения в `AliceCombat` нужны только ударам без своего отброса. Неуязвимости после попадания у Алисы нет, поэтому касание повторяется не чаще `_contactInterval` (0,5 с).

Попадание несёт тип удара (`HitKind`); враг показывает смерть по убивающему удару из `EnemySpriteSet`: у солдата укол — рана и мучения, разворот — обезглавливание, остальное — рассечение. Во время оглушения играет вздрагивание. Парирование (F или правый триггер) ловит удар спереди, если началось не раньше окна парирования этого удара (у копейщика 0,12 с до попадания; 0 — удар не парируется): урона нет, атакующий открыт на 1,2 с, и атака Алисы в течение 0,9 с после парирования — контратака на 2 урона. Удар, после которого у врага остаётся не больше `StunAtHealth` здоровья (у солдата 1), один раз за жизнь оглушает его на `StunnedTime` (2,5 с): враг не действует и подсвечен пульсирующим контуром (`ExecutionOutline`, шейдер `Alice/SpriteSilhouette`). Взаимодействие (E или верхняя кнопка геймпада) в пределах 3 тайлов от оглушённого врага — его казнь: Алиса встаёт на заданную дистанцию, её кадры и смерть врага идут синхронно, во время казни она неуязвима (`IExecutable` в `Alice.Core`; у солдата казнь `card_tear` — карта рвётся пополам: 14 кадров Алисы (захват 3, удар 3, рывок и отступ 8) на 0,3 + 0,35 + 0,65 с, Алиса встаёт в 2,4 тайла; ID казни в данных врага, кадры и тайминги Алисы под тем же ID в `AliceSprites` и `AliceCombat`). Атака казнь не запускает: оглушённого врага можно добить обычным ударом. Неудачное парирование держит Алису открытой до конца (0,5 с). Перехват удара — `IHitInterceptor`, открытие врага — `IParryable` в `Alice.Core`. Солдат — архетип EN09 без щита: щит и обход после промаха из GDD пока не сделаны. Дальность копья с шагом (3,15 тайла) укладывается в 3–4 тайла из GDD 0.16.

Урон и поражение Алисы (GDD, раздел 4). Попадание, которое не убивает, отбрасывает её и показывает три кадра вздрагивания (`HurtTime`, 0,3 с). При нуле здоровья `PlayerDamageReaction` проводит поражение по стадиям: падение — шесть кадров за 1,3 с, к концу экран темнеет (`ScreenFade` из `Alice.UI` рисует чёрный слой поверх экрана, холст создаётся в игре); полная темнота 0,5 с — в её начале Алиса переносится в начальную точку комнаты, здоровье восстанавливается и поднимается `Alice.Core.WorldReset`, по которому враги возвращаются на посты, как после отдыха; пробуждение — резкий вдох на коленях и подъём за 1 с, темнота уходит за первые 0,35 с. Всё это время ввод заблокирован и Алиса неуязвима. Времена — в `AliceCombat.asset`, кадры `alice_trial_hurt_`, `alice_trial_defeat_`, `alice_trial_wake_` — в `AliceSprites`.

Подкат и первый особый приём. Подкат нарисован четырьмя кадрами (`alice_trial_slide_`): срыв, два кадра скольжения на спине с ногой вперёд (не выше 1,5 тайла, проходят в проход высотой 2) и подъём, который показывается 0,08 с после подката на земле; серое тело больше не подменяет Алису. Удар с разворота — `TechniqueSpec` с ID `spin_strike` (`TechniqueIds`) в `AliceCombat.asset`: 0,18 + 0,32 + 0,26 с (видимый замах, оборот, пронос по инерции), 3 урона, зона по 2,2 тайла в обе стороны на высоте 1,2–2,8; задняя половина бьёт со своим направлением, чтобы враг за спиной падал от Алисы. Действие UseAbility (правая кнопка мыши или RB) выполняет выбранный приём из `PlayerLoadout` (пока он задан по умолчанию, выбор на отдыхе — в M3), если `ConfidencePool` может заплатить 30; без этого ничего не происходит. Убивающий разворот — смерть по типу Spin, у солдата обезглавливание; в конце кровь оседает в лужу (11 кадров). Кадры `alice_trial_spin_`: 16 кадров — присед с закручиванием (4), оборот хлёстом через спину, дальнюю сторону и лицо в выпад (8), пронос по инерции и выпрямление (4). Игла рисуется скриптом `needle.ps1`: на обороте её острие идёт по плоскому эллипсу вокруг тела, поэтому к камере и от неё она укорачивается, в дальней половине прячется за Алису, а за острием остаётся светлый след. Попадание ощущается: удар Алисы и враг замирают на 0,06 с (разворот и контратака — 0,11 с, враг — 0,08 с), камера дёргается на 1–2 пикселя (`Alice.Core.Impacts`, `CameraFollow2D`), при уроне Алисе — на 2; глобальное время не трогается.

Шкалы, соль и указы (GDD 0.20). Здоровье Алисы — «Ясность ума»: `Health` на 100 очков, выпад солдата снимает 20 (урон в данных врага). Нюхательная соль — `PlayerSalts`, действие Heal (Q или левый бампер): только на земле и без другого действия; при полной ясности заряд тратится впустую — каждый промах ощутим; 0,8 с с блокировкой движения, на 55 % возвращает 40 % шкалы; удар до этого момента тратит заряд впустую. 2 заряда, все возвращаются по `WorldReset` (поражение, позже отдых). Кадры `alice_trial_salts_`. Побеждённый враг сообщает о себе через `Alice.Core.EnemyDefeats`: награда указами и уверенностью — в его данных (солдат: 15 указов, 5 уверенности); `PlayerSpoils` засчитывает только убийства Алисы, казнь даёт втрое больше уверенности. «Уверенность» — `ConfidencePool` до 100, тратится приёмами по принципу «всё или ничего»; приёмов, которые её тратят, пока нет. Потеря указов на месте поражения появится вместе с отдыхом в M3. HUD — `Alice.UI.Hud` на префабе Алисы со стилем `Data/UI/HudSkin.asset`: холст поверх экрана с целым масштабом от 640×360, шкала ясности (длина растёт с максимумом, потерянная часть краснеет и сжимается), шкала уверенности, пузырьки соли из `Art/UI/Hud`; в правом верхнем углу — счётчик указов пиксельными цифрами 5×7 с тёмной обводкой (`PixelDigits`), без слов. HUD рабочий, его ещё стилизуют целиком. Иконки HUD импортируются тем же постпроцессором, что персонажи.

Тесты: EditMode — здоровье и фазы удара; PlayMode — уколы оглушают и убивают солдата, его выпад ранит и отбрасывает Алису, кадры укола сменяются по фазам удара, парирование открывает солдата и атака вплотную его казнит, слишком раннее парирование не срабатывает.

## Отдых, сохранение и потеря указов (M3)

Место отдыха — кресло лицом к игроку, две гигантские катушки и квадратная подушка на полу с двумя иглами длиной как у Алисы (`Alice.World.RestPoint`, префаб `Prefabs/World/RestChair.prefab`) с устойчивым ID вида `R_COMBAT_01`. Interact внутри его триггера запускает `Alice.Player.PlayerRest`. Алиса переносится к месту перед креслом, обратным хватом втыкает иглу в подушку, поворачивается к нам и садится за `_restSitTime` (2,4 с, `AliceCombat`). Затем срабатывает отдых:
- ясность восстанавливается;
- `WorldReset` возвращает врагов на посты и пополняет соль;
- кресло становится точкой пробуждения (`PlayerDamageReaction.SetWakePoint`);
- `Alice.Core.Autosave` просит сохранить игру.

Пока она дремлет, `Alice.UI.RestMenu` показывает значки известных приёмов (`PlayerLoadout.KnownTechniques`, значки в `HudSkin`). Влево-вправо экипирует приём сразу. Выше — ряд найденных карманных вещиц (`PlayerTrinkets.Found`) с квадратиком на каждый карман над ним (заполнен — карман занят). Вверх-вниз выбирают ряд; в ряду вещиц влево-вправо двигают курсор, Interact надевает или снимает вещицу (`PlayerTrinkets.Toggle`, при полных карманах не надевается). Встаёт она по Jump или Evade за `_restRiseTime` (1,6 с: те же кадры в обратную сторону, игла возвращается в руку). Удар поднимает её из кресла, а до того, как она уселась, отменяет отдых.

Кадры отдыха — `alice_trial_rest_00..26` в `AliceSprites` (`_restSit`: 8 кадров втыкания иглы и 19 кадров посадки; дремота `_restDoze` кивает по последним четырём кадрам). Кадры содержат только Алису и её иглу (холст 128×80). Реквизит — отдельные спрайты в `Art/World/Rest/`, каждый стоит на полу сам: кресло (`rest_chair`, сортировка 4), красная катушка (`rest_spool_red`, 5), синяя (`rest_spool_blue`, 6) и подушка с иглами (`rest_cushion`, 12, перед Алисой — она прячет вбитую часть её иглы). Смещения — целые пиксели от точки, где Алиса встаёт отдыхать (`AliceRestSetup.RestProps`). Импорт `Art/World/` настраивает тот же постпроцессор, что для персонажей.

Сохранение — `Alice.Save`:
- `SaveData` хранит версию схемы, ID кресла, указы, уверенность, потерю (ID комнаты, место, сумма), приёмы и способности;
- `SaveStore` пишет JSON во временный файл и заменяет им основной, предыдущий оставляет как `.bak`; испорченный файл не перезаписывается, вместо него читается копия;
- `SaveGame` (объект в сцене) на старте загружает `persistentDataPath/alice-save.json` и раздаёт части системам Алисы через `ISaveParticipant`, а на каждой точке автосохранения собирает и пишет.

Точки автосохранения: отдых, пробуждение после поражения (потеря уже лежит), новая способность, открытая дверь, убитый враг (указы и уверенность), подобранная потеря и трата уверенности на приём; при выходе из игры сохранение тоже пишется. Так выход и повторный вход никогда не откатывают добычу. Если в сохранении записано кресло этой комнаты, Алиса начинает в нём.

Потеря указов — `PlayerSpoils` (`Alice.Core.IDecreeLoss`). При поражении все указы ложатся на последнюю безопасную опору (`PlayerRespawn.SafePosition`), старая потеря пропадает. ID комнаты берётся из `Alice.World.Room` через `RoomPresence`. `Alice.World.DecreeCache` (префаб `Prefabs/World/DecreeCache.prefab`) показывает в этой комнате ромашку с указами вместо лепестков; она качается через `Alice.World.SpriteLoop`, 8 кадров по 0,18 с. Подбирает Алиса сама: Interact, когда её ноги не дальше `_lossPickupRadius` (1,2 тайла, `AliceCombat`) от ромашки, она стоит на земле и свободна (`PlayerSpoils.CanRecoverLoss`). Это нажатие не усаживает её в кресло, даже если оно рядом. Пока Алиса лежит после поражения, подобрать нельзя.

`Alice → Prototype → Add Rest To Open Scene` добавляет в открытую сцену комнату, кресло с катушками и подушкой у старта Алисы, ромашку для потерянных указов и сохранение. В арене и в комнате прохождения это уже сделано.
## Комнаты, переходы и постоянная дверь (M3)

Комната — отдельная сцена. В `Bootstrap` живут Алиса, камера (`CameraFollow2D` плюс Pixel Perfect), `SaveGame` и `Alice.World.RoomLoader` с каталогом `Data/World/Rooms.asset` (`RoomCatalog`: ID комнаты → сцена; первая запись — комната новой игры). В каждой сцене комнаты есть `Alice.World.Room`: устойчивый ID, границы камеры (`_controlsCamera`) и стартовая точка.

Переход:
- `RoomDoorway` — триггер в проёме стены. Когда в него входит Алиса, он просит `Alice.Core.RoomTravel` перейти к проёму следующей комнаты.
- Загрузчик затемняет экран (`ScreenDarkness`, 0,18 с), выгружает все сцены, кроме Bootstrap, и загружает нужную.
- Он ставит Алису в точку прибытия (`IArrivalSpot`: проём — 3,5 тайла внутрь лицом в комнату, кресло — сиденье) через `IRoomArrival` (`PlayerRespawn`, заодно сбрасывает безопасную опору), мгновенно переводит камеру (`CameraFollow2D.Snap`) и снимает затемнение.
- Пока идёт переход, Алиса не управляется.

Новая игра начинается в первой комнате каталога. Загрузка сохранения ведёт в комнату кресла (`SaveData.RestRoomId`). Поражение, если кресло в другой комнате, переносит туда в темноте.

Сцену комнаты можно запустить прямо из редактора: `Room` подгрузит Bootstrap, и Алиса начнёт в стартовой точке этой комнаты; сохранение её оттуда не уводит. Старые сцены `Prototype_Traversal` и `Prototype_Combat` работают сами по себе, как раньше.

Постоянная дверь — `Alice.World.PermanentDoor`:
- тело на всю высоту проёма перекрывает проход, защёлка с одной стороны (`_latchSide`);
- Interact со стороны защёлки открывает её: `Alice.Core.IInteractable`, использует `Alice.Player.PlayerInteractor`; подбор указов и кресло рядом имеют приоритет;
- открытие поднимает флаг мира `door:<ID>` (`Alice.Core.WorldFlags`, сохраняется в `SaveData.Flags`) и автосохранение;
- открытая дверь не закрывается ни отдыхом, ни поражением, ни перезагрузкой;
- кадры — `Art/World/Doors/door_00..08`, по 0,08 с.

Тестовая карта — `Alice → Prototype → Build M3 Rooms`: семь комнат цепочкой `Scenes/M3/M3_A..G`, конец которой возвращает к началу (GDD 0.24). Предмет каждой способности лежит перед её затвором:
- **A** — узел: кресло `R_M3A_01` и дверь-шорткат `D_M3A_W`, которая открывается только со стороны G;
- **B** — карточный солдат и веер (A01);
- **C** — уступ в 6 тайлов под восточным выходом, без веера не забраться;
- **D** — гриб (A02); выход — маленькая дверь, `RoomDoorway._requiresSmall`, на ней `LittleDoor`: Interact в зоне перед дверью — укус гриба, уменьшение и открытие, общий для обеих сторон флаг `door:LD_M3_D_M3_E`;
- **E** — Чеширский шаг (A03): провал шириной 12 тайлов, больше любого прыжка; `CheshireBridge` всегда мерцает и сам становится опорой, когда Алиса с Чеширским шагом подходит ближе 3 тайлов, и гаснет через 0,4 с после её ухода (GDD 0.25); падение (`FallHazard`) возвращает на берег;
- **F** — часы (A04): `ClockGuillotine` опускает лезвие поперёк прохода и поднимает слишком ненадолго, `ClockMarker` держит его поднятым 5 с;
- **G** — выход к двери в A с её закрытой стороны.

Реквизит затворов нарисован (Revision08): предметы способностей, метки гриба и часов, маленькая дверь, мост, лезвие и две стойки гильотины. Спрайты — `Art/World/Gates/gate_*`. Их ставит `Alice.Editor.AliceGateArtSetup`: построитель вызывает её для новых комнат, а `Alice → Prototype → Apply Gate Art to M3 Rooms` — для уже созданных. Затворы она находит по компонентам (`AbilityPickup` по ID способности, маркеры, `RoomDoorway` с `RequiresSmall`, `CheshireBridge`, `ClockGuillotine`). Серая заглушка заменяется дочерним объектом со спрайтом, стоящим на полу; мост перепривязывается к нему, чтобы проявлялся и гас именно рисунок. Без файла спрайта остаётся заглушка. Гриб — `Alice.Player.PlayerSize` (`IShrinkable`): хранит «маленькая или нет», включает `PlayerMotor.RunOnly` (без прыжка, подката и действий: их компоненты проверяют этот флаг вместе с `IsLocked`) и возвращает рост в 4 тайлах от места уменьшения (`_growDistance`), в другой комнате, при ударе и сбросе мира. Рисует её `PlayerSpriteView`. У маленькой Алисы свои кадры (Revision09, `alice_trial_small_idle_/run_/rise_/apex_/fall_/land_`, рост 27 px). При уменьшении она сначала откусывает гриб (`alice_trial_bite_`, 8 кадров по 0,08 с, Revision10), затем играет переход `alice_trial_shrink_` (8 кадров по 0,06 с), при возврате роста — он же в обратную сторону. Своих кадров нет только у действий: удары, парирование, реакции рисуются полноразмерными кадрами в масштабе `_smallFallbackScale` (0,5) из `AliceSprites`, как временная мера. Кадры назначает `Alice → Prototype → Attach Alice Sprites`.

Построитель создаёт сцены комнат один раз и больше их не трогает. `Alice → Prototype → Rebuild M3 Rooms (recreate scenes)` пересоздаёт их с нуля. Ещё построитель настраивает Bootstrap и добавляет комнаты в список сборки. Играть нужно из `Bootstrap` или из любой сцены M3.

### Карманные вещицы

Вещица — `Alice.Player.TrinketDefinition` в `Data/Trinkets` (ID `T01`…, значок, эффект данными: множитель получаемого урона, прибавка к окну парирования, лечение при казни). `PlayerTrinkets` на Алисе хранит найденные, надетые и число карманов (2, максимум 6), сохраняется и складывает эффекты надетых: урон меняет `Health` через `IDamageTakenModifier`, окно — `PlayerParry`, лечение — `PlayerAttack` при казни. Тайник `Alice.World.TrinketCache` отдаёт вещицу по Interact через `ITrinketReceiver` и исчезает навсегда. `Alice → Prototype → Set Up Trinkets` создаёт три первые вещицы (GDD 0.27), ставит компонент на префаб и тайники в M3: напёрсток в C на уступе для веера, пуговица в E за Чеширским мостом, конфетка в G. Значки — `Art/UI/Trinkets/trinket_T0N.png` (Revision11).

### Предметы-свёртки и окно находки

Все предметы в мире — свёрток `Art/World/Items/item_bundle_00..07` (Revision12): 8 кадров блеска, затем 14 кадров покоя по 0,12 с через `SpriteLoop`. `AbilityPickup` и `TrinketCache` открываются по Interact (зона 2×2 тайла) и объявляют находку через `Alice.Core.ItemNotice`. `Alice.UI.ItemPopup` на Алисе показывает по центру экрана значок и название из `ItemCatalog` (`Data/UI/ItemCatalog.asset`: ID → значок и `LocalizedString` из таблицы `Items`) 2,5 с с плавным появлением; несколько находок подряд идут по очереди. Шрифт — `Art/Fonts/FusionPixel/FusionPixel12-Latin.otf` (Fusion Pixel 12 px, SIL OFL 1.1, лицензии рядом), импорт 12 px, Hinted Raster, текстура глифов без сглаживания. `Alice → Prototype → Set Up Items As Bundles` создаёт таблицу Items (ru/en), каталог, ставит окно на префаб и свёртки во все комнаты M3; уже заполненные строки и записи каталога не трогает. Подбор: `BundleOpening` (общий для `AbilityPickup` и `TrinketCache`) отдаёт предмет сразу (и он сохраняется), а Алиса через `Alice.Core.IItemPicker` (`Alice.Player.PlayerPickup`) поворачивается к свёртку, встаёт так, чтобы он лёг под её нарисованную руку (`_reach` 0,94 тайла), и 1,3 с наклоняется, берёт его, держит у груди и прячет в фартук (`alice_trial_pickup_00..14`, Revision13). Свёрток лежит на полу до захвата (`_grabTime` 0,35 с), затем исчезает и появляется окно находки.

### Арт комнат Нижних покоев

Запекатель `Alice.Editor.AliceRoomArtBaker` (Revision14) кладёт арт биома поверх серых блоков открытой сцены. Геометрия по-прежнему одна — блоки построителя с их коллайдерами; их серые рендереры выключаются, а под корнем комнаты появляется `LowerQuartersArt` с тремя спрайтами:

- `BackWall` — задняя стена из блоков-декораций (порядок −100): та же текстура кладки, затемнённая и сдвинутая, чтобы её камни не совпадали с камнями массива;
- `Masonry` — сплошные блоки (порядок 0): внутри — текстура `lq_fill_masonry` 128×128 по мировым пикселям (повтор раз в 8 тайлов), край шириной 4 px — из углового Wang-тайлсета, разложенного двойной сеткой (тайл сдвинут на полтайла и берёт углы из четырёх соседних клеток, поэтому нарисованный край совпадает с краем коллайдера);
- `Catwalks` — сквозные платформы (порядок 1), доски из своего Wang-тайлсета.

Клетка принадлежит блоку, если её центр внутри блока; клетки за пределами комнаты считаются массивом, поэтому наружные стены уходят за край без обводки. Ловушки (триггеры) и прочие объекты не трогаются.

Исходники — `Art/World/LowerQuarters/Source`: `lq_fill_masonry.png`, `lq_rim_tile.png` (верх — светлая плитка прачечной), `lq_rim_slab.png` (мокрые плиты с водорослями — для затопленной зоны), `lq_rim_plank.png`. Тайлсеты переупорядочены скриптом `Revision14/pack-wang.ps1`: тайл с углами NW, NE, SW, SE лежит под номером NW·8 + NE·4 + SW·2 + SE. Запечённые PNG — `Art/World/LowerQuarters/Baked/<сцена>_backwall|masonry|catwalks.png` (спрайт, 16 px на юнит, Point, пивот снизу слева). Папки `Baked` исключены из `AliceCharacterArtPostprocessor`: он ставит всему в `Art/World` пивот снизу по центру, и 8 ноября 2026 это сдвинуло запечённую комнату влево на половину ширины. Запекатель к тому же ставит слой по фактическому пивоту спрайта, а тест `BakedArtLinesUpWithTheBlocks` проверяет, что слои покрывают ровно клетки блоков.

Меню:

| Пункт | Что делает |
| --- | --- |
| `Alice → Art → Build Lower Quarters Test Scene` | Создаёт копию `Prototype_Traversal` — `Scenes/Prototype_LowerQuarters`, запекает с плиткой и сохраняет. Не работает, если в открытых сценах есть несохранённые изменения |
| `Alice → Art → Bake Lower Quarters Art (Laundry Tiles)` / `(Wet Slabs)` | Запекает открытую сцену с выбранным верхом; сцену нужно сохранить |

Повторный запуск перезаписывает те же файлы и использует те же объекты. Изменили блоки — запекают заново. Края комнаты продолжаются наружу (крайняя клетка повторяется), поэтому проём у самого края комнаты остаётся открытым и на рисунке.

### Палитра уровня

`Alice → Level Palette` — окно для сборки комнат (`AliceLevelPaletteWindow`). Подписи в нём русские: окно для владельца, игроку оно не видно.

**Размеры.** Кнопка «Размеры» в шапке палитры (с подсказкой) и меню `Alice → Level → Sizes` открывают окно `AliceLevelMetricsWindow` со всеми размерами для левел-дизайна: пределы для комнат, прыжок (высота, самый короткий, время в воздухе, дальность с разбега на ту же высоту, на уступы +1…+4 и вниз), веер A01 (второй прыжок: подъём, наибольшая высота, дальности), бег, подкат, падение, койот и буфер прыжка, тело и экран, гриб, Чеширский мост, гильотина, обзор и выпад солдата. Всё считается при открытии из `TraversalMetrics`, `AliceMovement.asset`, `CardSoldier.asset` и префабов затворов (`AliceLevelMetrics`), руками ничего не вписано. Дальности — по физике мотора (подъём под гравитацией, падение под более сильной до предела скорости) без ширины тела и койота, поэтому на деле чуть больше. Кнопка «Копировать» кладёт список в буфер таблицей Markdown. Тесты — `LevelMetricsTests`.

**Комната.** «Новая комната» с ID создаёт `Scenes/Rooms/<ID>.unity` с `Room`, корнями `World` и `Gameplay`, ромашкой потерянных указов, добавляет комнату в каталог `Data/World/Rooms.asset` и в сборку (перед этим предлагает сохранить открытые сцены). «Камера по массиву» ставит границы камеры по нарисованному массиву, «Точка старта» — щелчок в окне сцены задаёт старт комнаты. «Проверить комнату» (`AliceLevelRoomTools.Validate`) находит: нет `Room` или его ID, комнаты нет в каталоге, повтор ID, проём без цели или с целью вне каталога, недописанный ID маленькой двери (`TODO`), метка часов без механизма, нет ромашки указов. «Запечь: плитка / плиты» — запекатель арта из предыдущего раздела.

**Карта биома.** У `Room` есть мировое положение (`WorldPosition`, тайлы, левый нижний угол локальных координат комнаты); в палитре оно задаётся полем «Место на карте биома». Кнопка «Карта биома» (`Alice → Level → Biome Map`, `AliceLevelWorldWindow`) открывает все комнаты из `Scenes/Rooms` на одной карте с подписями и проверкой `AliceLevelWorld.Check`: комнаты не накладываются; каждая непустая клетка на краю комнаты продолжается непустой клеткой соседа на тех же мировых координатах — иначе «проход упирается в стену»; край без соседа — «проход ведёт туда, где нет комнаты»; цель проёма должна примыкать к нему на карте. Сцены, которые не открыты, читаются и закрываются без сохранения. Тесты — `LevelWorldTests`.

**Геометрия** (`AliceLevelGeometry`). Четыре кисти: массив, мостки, опасность, задняя стена. В окне сцены протянуть мышью — залить прямоугольник клеток, с Shift — стереть, Esc — выйти. Клетки хранятся в скрытых `Tilemap` (`World/LevelGrid/<кисть>`, тайлы `Art/Prototype/LevelTiles`) — это только данные, с отменой Unity. После каждого мазка `World/Geometry` пересоздаётся из них теми же серыми блоками, что делают построители: массив, опасность и стена сливаются в прямоугольники, мостки — по одному блоку на горизонтальный ряд (спрыгивание игнорирует коллайдер целиком, общий блок уронил бы Алису сквозь все мостки ниже). Массив или мостки поверх другой кисти заменяют её; задняя стена лежит под всем. Блоки построителей в других местах сцены не трогаются.

**Объекты** (`AliceLevelPaletteCatalog`). Категория — папка `Prefabs/Level/<Категория>`, её объекты — префабы в ней: новый префаб, положенный туда, сразу появляется в палитре. Известные папки подписаны по-русски: Rest — «Отдых», Transitions — «Переходы», Gates — «Затворы», Items — «Находки», Enemies — «Враги», Props — «Реквизит», Service — «Служебное». «Заполнить из готовых» (`Alice → Level → Fill Palette From Existing Objects`) создаёт недостающие: варианты кресла, солдата и ромашки и копии объектов из комнат M3 — проём, маленькая дверь, дверь-шорткат, мост Чеширского Кота, гильотина, метка часов, свёртки способностей A01–A04 и вещиц T01–T03. Сцены M3 открываются дополнительно и закрываются без сохранения; уже существующие префабы не перезаписываются.

Щелчок по объекту в палитре, затем в окне сцены: объект встаёт под `Gameplay` низом своих видимых или твёрдых частей на линию сетки под курсором, по горизонтали — на целый или половинный тайл. Палитра сама даёт ID с префиксом комнаты: проём `D_<комната>_01`, дверь-шорткат `SD_…`, кресло `R_…`; маленькой двери нужен ID обеих комнат, поэтому её ID — `LD_<комната>_TODO`, пока его не допишут. Метка часов привязывается к ближайшей гильотине. Цель проёма (комната и проём) задаётся в инспекторе.

EditMode-тесты `LevelPaletteTests`: размеры и виды блоков из клеток, мостки по рядам, опасность — триггер с `FallHazard`, замена кисти, стирание, камера по массиву, проверка комнаты, ID и посадка на пол у настоящих префабов палитры.

### Серые комнаты Нижних покоев

`Alice → Level → Build Lower Quarters Grey Rooms` (`AliceLowerQuartersBuilder`) собирает по [схеме комнат](LowerQuartersRooms.md) сцены `Scenes/Rooms/L01..L08`: стены толщиной 2 и потолок, полы, мостки, ямы и проёмы высотой 4 рисуются кистями палитры (`AliceLevelGeometry.SetCells`, блоки пересобираются один раз), объекты ставятся из каталога палитры. Проёмы получают ID вида `D_L01_E` и цели в соседних комнатах, прибытие — 3,5 тайла внутрь; комнаты попадают в каталог `Rooms.asset` и в сборку. Комнаты стоят на мировой карте петлёй (положения — в [схеме комнат](LowerQuartersRooms.md), раздел 1): нижний ярус L01–L03 на восток, высокий L04, верхний ярус L05–L08 на запад; лифт L06 → L02 пока сделан падением через проём в полу L06 и потолке L02 (вертикальные `RoomDoorway` с триггером в проёме). Ямы — опасность над сплошным дном, чтобы край комнаты на карте оставался закрытым. Построитель создаёт только недостающие сцены; `Rebuild Lower Quarters Grey Rooms (recreate scenes)` пересоздаёт все восемь, и ручные правки в них теряются. Дальше комнаты правят палитрой.

Временные замены: лакея и сборщика изображает карточный солдат, ключ Додо — дверь-шорткат в L07 с защёлкой со стороны арены, засов L03 — та же дверь, лифт — падение. Ещё не собраны (нет механики, графики или комнаты): подъём на лифте, H00, H01, L10, трубы с паром, сцена с иглой, Мать-Краб, Додо, «Выпей меня» на полке L01, боковые места L09–L12 (их проёмы L10 в L02 и шахты в L01 и L08 прорезаны, но никуда не ведут).

### Карта в игре

Карта (GDD 0.33, 0.34) собрана из трёх частей, все по устойчивым ID:

- **Данные** — `Data/World/MapAtlas.asset` (`Alice.World.MapAtlas`): зоны (ID, `LocalizedString` названия, оттенок), комнаты (ID, зона, тайная ли, мировое положение и прямоугольник, клетки строкой: `#` камень, `.` воздух, `-` мостки, `~` опасность) и неподвижные значки (вид, комната, мировая точка, ID предмета в свёртке). Атлас запекается из сцен `Scenes/Rooms` командой `Alice → Level → Bake World Map` (`AliceMapSetup.BakeAtlas`); построитель Нижних покоев перепекает его сам. Значков два вида, только то, что Алиса находит: кресло (`RestPoint`) и свёрток (`AbilityPickup`, `TrinketCache`) — значок свёртка пропадает, когда предмет у Алисы (`BundleItems.AliceHas`). Затворы, двери, лифты и опасности на карту не попадают (правка владельца, GDD 0.34). Зона и тайность комнаты — поля `Room` (`ZoneId`, `Secret`). Новая зона: комнаты со своим `ZoneId`, запись зоны в `AliceMapSetup.Zones` (или прямо в атласе) и строка `map.zone.<ID>` в таблице UI; код карты не меняется.
- **Прогресс** — `Alice.World.MapProgress` на Алисе (`ISaveParticipant`) с логикой в `MapState`. Карта открывается по клеткам: когда Алиса переходит в новую клетку, `Explore` кладёт на карту открытые клетки текущей комнаты в радиусе `_exploreRadius` (9 тайлов), до которых можно дойти от неё, не проходя сквозь камень (поиск в ширину по клеткам атласа). Комната «раскрыта», если открыта хоть одна её клетка. `RevealZone` раскрывает зону целиком без тайных комнат. Отметки игрока (до 64) ставятся и снимаются в радиусе 2 тайлов. В `SaveData` — `MapCells` (по комнате битовая строка открытых клеток в Base64), `MapWholeRooms` и `MapMarks`; поле `MapRooms` из сохранений 0.33 больше не читается — такая карта начинается заново.
- **Экран** — `Alice.UI.MapScreen` на Алисе (холст uGUI в коде, как у меню отдыха; целое масштабирование от 640×360). Действие `Gameplay/Map` (M / Select) открывает и закрывает, Evade закрывает. Пока карта открыта, мотор Алисы заперт, мир идёт дальше. Курсор в центре окна двигается стиком, Interact ставит или снимает отметку, Heal и UseAbility меняют вид отметки, карта открывается в масштабе комнаты (8 пикселей на тайл, в окне около 52 × 32 тайлов вокруг Алисы), Jump переключает на обзор (2 пикселя на тайл) и обратно. `MapPainter` рисует только открытые клетки выкройкой (бумага в клетку, мел, пунктир мостков; линии толще в масштабе комнаты; опасности не отмечаются; поля бумаги закрывают окно при любом масштабе), `MapGlyphs` — значки 7×7 кодом. Подписи легенды, подсказки и название «неизвестных мест» — `Data/UI/MapSkin.asset` (`MapSkin`, строки `map.*` таблицы UI); картинка у знака в скине заменяет нарисованный кодом.

`Alice → Prototype → Set Up Map` (`AliceMapSetup.SetUp`) создаёт строки ru/en, скин, атлас и компоненты на префабе Алисы; повторный запуск ничего не перезаписывает. В автоматизации — `Alice → Automation → Press Map`. Повторный запуск `Set Up Map` убирает из таблицы и скина строки значков, которых больше нет, и обновляет подсказку, если её не правили вручную. Тесты — `MapTests` (открытие вокруг Алисы, камень останавливает открытие, старт с клетки над полом, тайные комнаты, отметки, сохранение, перевод в мировые координаты, отрисовка только открытого и открытые проходы).

Каждый компонент Unity лежит в файле со своим именем: иначе сцена получает сломанную ссылку на скрипт, и компонент молча не работает.

### Главное меню

Главное меню (GDD 0.35) — сцена `Scenes/MainMenu.unity`, первая в Build Settings. В ней камера и объект с `Alice.UI.MainMenu`; экран строится в коде из `Data/UI/MenuSkin.asset` (`MenuSkin`: шрифт Fusion Pixel, фон, логотип, курсор-ключ, атлас карты для названия зоны, все подписи — `LocalizedString` строк `menu.*` таблицы UI). Целое масштабирование от 640 × 360; фон 320 × 180 рисуется вдвое. Ввод — uGUI `EventSystem` с `InputSystemUIInputModule` на карте UI из `AliceInput` (Navigate, Submit, Cancel, Point, Click): стик, стрелки, мышь. Строка меню — `MenuLine` (`Selectable`): Submit подтверждает, влево и вправо меняют значение настройки, Cancel — назад.

- **Слоты.** `Alice.Save.SaveSlots`: три файла `alice-save-1..3.json` в persistentDataPath; меню ставит `SaveSlots.Current` и грузит сцену игры (`MenuSkin.GameScene`, Bootstrap). `SaveGame` пишет в текущий слот и добавляет в `SaveData` сводку: `RoomId`, `PlayTime` (секунды), `SavedAtUtc`. Комната, запущенная в редакторе сама по себе, играет в слоте 1. Старый одиночный `alice-save.json` при первом чтении слотов становится слотом 1, если тот пуст. Новая игра начинается в первой комнате каталога `Rooms.asset` (сейчас M3_A).
- **Настройки.** `Alice.Core.GameSettings` — `settings.json` отдельно от слотов: язык (пусто — как в системе), полный экран или окно ×2–×4, вертикальная синхронизация, громкость общая (уже управляет `AudioListener`), музыки и звуков (для будущего микшера), тряска камеры (`CameraFollow2D.Shake`). Применяются при старте игры и сразу при изменении; в редакторе размер окна не трогается.
- **Старт с меню.** `AlicePlayStart` ставит `EditorSceneManager.playModeStartScene` на меню перед каждым Play, какая бы сцена ни была открыта. Чтобы проверить одну комнату саму по себе, выключить `Alice → Play From Main Menu` (настройка этой машины, по умолчанию включена). PlayMode-тесты не затрагиваются: при запуске из тестовой сцены старт с меню пропускается. Автоматизация в Play (`Alice/Automation`) теперь начинается в меню: чтобы попасть в игру, выбрать слот (Submit дважды) или выключить старт с меню.
- **Арт и пасхалка.** `Art/UI/Menu`: `menu_background.png` (Pixen), `menu_logo.png`, `menu_cursor.png`; происхождение — `Art/Reviews/Alice/Revision16`. Логотип собирает `Revision16/menu/compose-logo.ps1`: буквы Pro Flash на табличке с ровной заливкой (14, 12, 22) и золотой рамкой; в заливке под буквами строкой 5 × 7 цветом (15, 13, 24) написано «Alisa K. 25.01.22» — пасхалка владельца, видна при поднятых яркости и контрасте. Не пережимать логотип, не менять заливку таблички и импорт (без сжатия, точечный фильтр), иначе строка пропадёт или станет видна всем.

`Alice → Prototype → Set Up Main Menu` (`AliceMainMenuSetup`) создаёт строки ru/en, скин, сцену и ставит её первой в сборку; повторный запуск ничего не перезаписывает. Тесты — `SaveSlotsTests`.
## Git и проверка

Коммитить `.meta`, текстовые сцены, настройки и lock-файл. Проверять `git status --short` перед коммитом. Не добавлять Library, Temp, Logs, сборки, локальные ключи и рабочую папку `work`.

Git LFS настроен в `.gitattributes`: PSD/PSB, KRA, TIFF/TGA/EXR, звук (WAV, AIFF, FLAC, OGG, MP3), видео, шрифты, FBX, Blend и архивы. PNG и Aseprite остаются в обычном Git: пиксель-арт мал, а квота LFS на GitHub ограничена. В клоне один раз выполнить `git lfs install --local`.

Проверка фундамента: импорт пакетов, отсутствие ошибок компиляции, успешный запуск ConfigureBatch и наличие созданных сцен/ввода. Это не проверка игрового поведения: игровых систем пока нет.
