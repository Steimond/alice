# Правила для агентов

Общие правила для любых ИИ-агентов и людей, которые меняют этот репозиторий. Проект ведёт один разработчик; код пишут разные агенты, поэтому стиль и границы систем должны совпадать.

## Проект

Alice — жестокая 2D soulslike-метроидвания по «Алисе в Стране чудес», рейтинг 18+. Unity 6000.6.6f1, URP 2D, Input System, Unity Localization. Детальный пиксель-арт уровня Blasphemous.

Источник истины по дизайну — [GDD](Docs/GameDesignDocument.md), по технике — [TechnicalSetup](Docs/TechnicalSetup.md), по этапам — [план разработки](Docs/DevelopmentRoadmap.md). Не реализовывать то, что противоречит GDD; при расхождении спросить владельца.

## Документация

- Документы пишем по-русски, идентификаторы в коде — по-английски.
- Markdown в `Docs/` — исходник. `Docs/GameDesignDocument.html` собран из восьми md-документов; после правки md внести тот же текст в HTML вручную (PowerShell 7 для `Build-ReadingEdition.ps1` на машине владельца не установлен).
- Принятые решения записывать в журнал решений GDD (раздел 16) и поднимать версию документа.
- Документы могут параллельно править другие агенты: перед правкой перечитать файл.

## Unity

- Сначала Unity CLI (`C:/Users/user/AppData/Local/Unity/bin/unity.exe`), затем Unity MCP, затем batch mode и правка файлов.
- Сцены, префабы и `.asset` создавать через Editor API, не вручную. Сохранять GUID и существующие `.meta`; новые `.meta` создаёт Unity и они коммитятся.
- Не запускать batch-Editor, пока проект открыт в обычном Editor.
- Повторяемая настройка проекта — `Alice.Editor.AliceProjectSetup.ConfigureBatch`. Она должна оставаться идемпотентной и не затирать пользовательские изменения.
- Генеративные инструменты для ассетов — только по явной просьбе владельца.

## Код

- Сборки: `Alice` (`Assets/_Alice/Scripts`, runtime), `Alice.Editor` (`Assets/_Alice/Editor`), тесты — `Alice.Tests.EditMode` / `Alice.Tests.PlayMode` в `Assets/_Alice/Tests`. Новые зависимости между сборками добавлять явно в `.asmdef`.
- Пространства имён повторяют папки: `Alice.Player`, `Alice.Combat`, `Alice.Abilities`, `Alice.World`, `Alice.Narrative`, `Alice.Save`, `Alice.UI`, `Alice.Core`.
- Стиль C#: четыре пробела, фигурные скобки на новой строке и всегда у `if`; `PascalCase` для типов, методов, свойств и констант; `_camelCase` для приватных полей; `[SerializeField] private` вместо публичных полей; `var` только когда тип очевиден справа. Комментарии объясняют «почему», а не пересказывают код.
- Системы разделены, как в GDD раздел 13: движение, боевая реакция, способности, состояние мира, диалоги, сохранения. Компонент не лезет в чужую систему напрямую — через интерфейс, событие или общий сервис из `Alice.Core`.
- Устойчивые строковые ID (`A01`, `L03`, `E04`) для способностей, комнат, эпизодов, флагов и сохранений. Никогда не опираться на имя объекта, порядок в списке или позицию в иерархии.
- Параметры движения, боя, врагов и вещиц — в `ScriptableObject` в `Assets/_Alice/Data`, а не константами в коде. Враги — архетип поведения в коде плюс данные варианта.
- Время: способность часов действует через интерфейс механизма; глобальный `Time.timeScale` для игровых эффектов не трогать. Физика и платформенные дистанции не должны зависеть от частоты кадров.
- Ввод только через Input System и `AliceInput.inputactions`; без `UnityEngine.Input` и жёстко прописанных клавиш.
- Пиксель-арт: целые пиксели на юнит из GDD раздел 12, Pixel Perfect Camera, без субпиксельного дрожания спрайтов.

## Локализация

- Никаких видимых игроку строк в коде, сценах и префабах. Все тексты — в таблицах `Assets/_Alice/Data/Localization` через `LocalizedString`.
- Исходный язык — русский (`ru`), второй — английский (`en`); язык системы, которого нет, откатывается на английский.
- Текстуры с надписями — локализуемые ассеты (`LocalizedTexture` / `LocalizedSprite`).
- Интерфейс рассчитан на тексты разной длины; шрифты покрывают кириллицу и латиницу.

## Проверка

- Различать проверку файлов, компиляцию и запуск игры; в отчёте писать, что именно проверено.
- После изменения кода — компиляция без ошибок и предупреждений из нашего кода. Логика без сцены — EditMode-тесты; поведение в сцене — PlayMode-тесты или ручной запуск.
- Перед повтором неудачного действия проверить, не выполнилось ли оно уже.

## Git

- Коммитить `.meta`, `Packages/packages-lock.json`, `ProjectSettings`. Не коммитить `Library`, `Temp`, `Logs`, `UserSettings`, сборки и `work/`.
- PSD, звук, видео, шрифты и архивы идут через Git LFS (см. `.gitattributes`); PNG и Aseprite — обычным Git.
- Коммиты и push — только по просьбе владельца. После законченного изменения предложить короткое сообщение коммита.
